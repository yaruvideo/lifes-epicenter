# Project management, one person sized

A short guide for running projects (Yaru Videos, DD2 series, Game Dev, home) around a day job. Each step is a plain-language version of a standard project management step. CAPM study terms are in brackets so they connect later.

## When something new starts

1. **Write the goal in one sentence.** What does "done" look like, and why does it matter? [Project charter]
   - Example: "A portfolio page with a reel and 3 to 5 pieces, so I can pitch clients by Dec 13."
2. **Say what's out.** One line on what this project will not do yet. This stops it growing. [Scope]
   - Example: "No paid website or custom domain until I have a paying client."
3. **Break it into pieces you can finish in one sitting** (about 1 to 3 hours). If a piece feels vague, split it again. [Work breakdown structure]
   - In the app: the project is a task, the pieces are its sub-tasks.
4. **Put a date on every piece, working backwards from the end date.** Leave the last week as a buffer. Sundays work well as due days. [Schedule, milestones]
5. **Mark what waits on what.** If B can't start until A is done, use "Waiting on" in the app. [Dependencies]
6. **Write down the one or two things most likely to go wrong, and what you'd do.** [Risk register]
   - Example: "Rupert can't record Nov 8. Backup: record Imani's lines with Hannah that week instead."
7. **Check the load.** Count your free hours for the week. If the pieces due that week need more, move a date now, not the night before. [Resource planning]

## Every week (15 minutes, Sunday)

Pair it with the weekly planning with Hannah.

- [ ] What got done? Tick it in the app.
- [ ] What's late? For each late item, pick one: do it this week, move the date, or drop it.
- [ ] What's due in the next 7 days? Star those for My Day on the right days.
- [ ] Anything blocked or waiting on someone? Send one nudge.
- [ ] Is only one narrative project active? (Rule agreed Oct 21.)

[Monitoring and controlling]

## When a date slips

1. Move the date in the app. Don't leave it red.
2. Check what depends on it and move those too.
3. Keep the end date if you can by shrinking the work; move the end date only if you can't. That's what we did with the brand plan on Oct 27. [Change control]
4. Write one line in the task notes saying why it moved, so the pattern is visible later. [Lessons learned]

## When a project ends

- [ ] Mark it done and write the wrap-up note (it goes to the Journal).
- [ ] Three lines: what went well, what didn't, what you'd change next time. [Retrospective]
- [ ] Move anything left over to a new task or drop it on purpose.
